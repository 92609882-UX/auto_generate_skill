# 参考包「零雾构想 v5003」的整包做法

这份文档记录参考包 **零雾构想 v5003（2025-10-02，作者 零雾〇五 Fogg05）** 除了"方块 `_n`/`_s` 怎么算"之外的全部做法：物品、实体、盔甲、纹饰、连接纹理、模型改动、版本适配、包装。

数据是把 zip 解开逐张统计出来的（8839 张 png）。**参考包只是参考，不是标准答案**；和作者既定规则冲突的地方，以作者为准（见 `training_log.md` 第二节）。

---

## 1. 包体结构

```
pack.mcmeta                  pack_format 15，supported_formats [1, 64]，min/max_format 1/9999
pack.png                     128×128
assets/minecraft/
  textures/block/            1282 底色 + 1264 _n + 1272 _s
  textures/item/             799 底色 + 799 _n + 800 _s
  textures/entity/           72 底色 + 72 _n + 72 _s
  textures/models/armor/     15 底色 + 15 _n + 15 _s
  textures/trims/…/armor/    1140 底色 + 1140 _s（没有 _n）
  textures/font/             64 张自定义字形
  textures/gui/              11 张（标题背景等）
  models/                    585 个 json（自定义几何 + 随机变体）
  blockstates/               122 个 json（随机变体、树叶、矿石等）
  optifine/texture.properties   format=lab-pbr/1.3
  optifine/ctm/              2 组连接纹理（泥土、下界岩）
  optifine/color.properties  加载界面配色
  font/default.json + uniform.json  自定义字形映射
  lang/zh_cn.json            覆写不兼容提示
```

- **没有** `shaders/`、`iris/`、`fabric.mod.json`：材质包只负责贴图，光影由玩家自己装（Iris / OptiFine + 支持 PBR 的光影包）。
- LabPBR 的声明只需要一行：`assets/minecraft/optifine/texture.properties` 里写 `format=lab-pbr/1.3`。Iris 和 OptiFine 都认它。

## 2. 分辨率：方块 / 物品 / 实体一律 8 倍

| 目录 | 底色原尺寸 | 包里的尺寸 | 倍数 |
|---|---|---|---|
| 方块 | 16×16（少数更高） | 128×128 | ×8 |
| 物品 | 16×16 | 128×128 | ×8 |
| 实体 | 64×64 / 64×32 等 | 512×512 / 512×256 / 1024×1024 | ×8 |
| 盔甲层 `models/armor` | 64×32 | 512×256 | ×8 |
| 盔甲纹饰 `trims` | 64×32（腿 16×16） | 原样 | ×1 |
| 字体、GUI | — | 原样 | ×1 |

放大到 8 倍的目的是让法线和 AO 有平滑的过渡（1 个原始像素 = 8×8 块）。纹饰和字体不放大，因为它们是薄贴花/图标。

**注意**：方块的 128×128 不总是严格的"每个 8×8 块一个纯色"。石头、草方块顶面是纯 8×8 块；沙子、物品这类作者在高分辨率上又画了细节（实测 8×8 块内有 30%–44% 不是纯色）。所以 `load_texels()` 取每块中心像素只是近似，遇到细节多的贴图要以看图为准。

## 3. `_n`/`_s` 的覆盖范围

| 情况 | 有没有 `_n` | 有没有 `_s` | 例子 |
|---|---|---|---|
| 普通实体方块面、物品、实体、盔甲层 | 有 | 有 | 石头、苹果、箱子 |
| 盔甲纹饰 | **没有** | 有 | `eye_iron`、`tide_gold` |
| 破坏裂纹 `destroy_stage_01..10` | 没有 | 没有 | 方块被挖时的裂纹叠加层 |
| 火 / 灵魂火 / 营火火 / 岩浆 / 传送门 | 没有 | 有 | `fire_0`、`lava_still`、`nether_portal` |
| 字体、GUI | 没有 | 没有 | — |

规律：**只要有 `_n` 就一定配了 `_s`，反过来不一定**（纹饰、火、岩浆只有 `_s`）。透明的叠加层（裂纹）两个都不做。

参考包里 **没有 `_e` 贴图**：自发光一律走 `_s` 的 A 通道。新版原版的 `*_emissive` 命名贴图（`firefly_bush_emissive`、`open_eyeblossom_emissive`）也照常配 `_n`/`_s`。

## 4. 物品 / 实体 / 盔甲层：平面高度 + 保留浮雕

这一类都是"贴在平面上的精灵图"，做法和方块不一样。实测结果：

| 通道 | 透明像素 | 不透明像素 |
|---|---|---|
| `_n` R / G | 127（平） | 围绕 127，实测最宽到 76–184（物品）、25–227（实体）。与底色的明暗边缘相关，实测相关系数约 0.64–0.67 |
| `_n` B（AO） | 255 | 大部分 255，暗处/对比强处降到约 50–110 |
| `_n` A（高度） | **255** | **255**（整张都是 255，不做视差） |
| `_s` R | 0 | 按材质映射到该材质的 R 范围（苹果 11–181、铁剑 35–221、钻石 37–207） |
| `_s` G | 0 | 按材质表（非金属 0；铁剑出现 232/235/240/245/250/252/255；钻石 0/255） |
| `_s` B | 0 | 0（这一类都不给孔隙度/SSS） |
| `_s` A | 255 | 255（不发光；发光物品另说） |

可以这样理解作者的做法：

1. 照常从底色的明暗算出一份高度图，用它生成窄法线和 HBAO。
2. **但把 `_n` 的 A 通道全部写成 255**，让精灵保持平面、不产生视差错位。
3. B 通道的 AO 保留下来 → 精灵自己有一点内阴影，看起来更立体。
4. 透明背景要"洗干净"：`_n` 写 127/127/255/255，`_s` 写 R=G=B=0、A=255，免得背景渗出色边。

对应脚本参数（本轮新加）：

```python
tex = lg.load_texels('item/apple.png')
n, H = lg.build_n(tex, lower=200, flat=True, flat_ao=True, transparent_flat=True)
s = lg.build_s(tex, r_range=(20, 180), g=0, b=0, clear_alpha=True)
```

- `flat=True`：A（高度）写 255。
- `flat_ao=True`：平面高度但仍然算 AO（不加这个参数，AO 也会被关掉）。
- `transparent_flat=True`：透明像素写成 127/127/255/255。
- `clear_alpha=True`（`build_s`）：透明像素的 R/G/B 清零，A 仍是 255。

### 新一轮「尝鲜·立体模型」包核对（2025-10 / 2025-11）

作者在 v5003 之后又把整包拆成了四个「立体模型」小包（门、床、工作方块、常规）。
把它们解开逐张量了一遍，用来核对上面这套做法，也补到几个新数字：

| 包 | 内容 | 底色 / `_n` / `_s` |
|---|---|---|
| 门 | 门、活板门 | 87 / 85 / 85 |
| 工作方块 | 工作台、酿造台、书架、铁砧、钟、讲台… | 58 / 55 / 55 |
| 常规 | 铁轨、铁栏杆、梯子、甘蔗、作物、锁链、紫水晶… | 58 / 55 / 55 |
| 床 | `textures/entity/bed/*`（16 色床） | 17 / 16 / 16 |

**实体（床）实测：**

- 64×64 → **512×512**，确认实体也是 8 倍。
- `_n` A（高度）整张 255（100%），平面、不做视差 —— 和上表一致。
- `_n` B（AO）大部分 255（82.7%），最暗到 **152**，比物品更轻。
- `_n` R/G 的法线**很强**：偏离 127 最大到 **210**（约 ±105），**48% 的像素不是平的**。
  实体贴图的法线不是「只在明暗边缘 1 像素」，而是整个 UV 块都有起伏，
  做的时候不要用方块的窄法线强度去压它。
- `_s` R 0–150（中位 66）；`_s` G 全是 **0**；`_s` A 全是 255（不发光）。
- `_s` B = **0 / 8 / 20**：v5003 的实体 B 全是 0，这一版给床单/布料加了孔隙度。
  所以实体不一定要把 B 压成 0，布、羊毛这类按材质表给 8–20 更贴合。

**模型方块实测（门 / 工作方块 / 常规）：**

- 门、活板门、铁轨、梯子、栏杆、锁链、作物、蘑菇、甘蔗这类「没有实体面」的，
  `_n` A 整张 255（门 85 张、常规 54 张全是 255）——和高度分档表「无高度」一档对得上。
- 工作方块里真有开口/凹洞的（铁砧、木桶、讲台、织布机、切石机），A 最低到 **87**，
  其余表面仍在 255 附近，属于「真实凹洞」那一档。
- `_s` G 里出现 230（铁）、231（金）、232（铝）、255（其他金属），也有作者惯用的
  243/249 这类未定义值 —— 我们仍按规范填，不照搬。
- 门包的模型还引用了 `item/copper_door` 这种 1.21.4+ 的 `items/` 定义；
  做整包时物品图标要跟着一起覆盖。

**顺手发现的问题**：常规包的 `block/copper_bars.png` 只有底色、没配 `_n`/`_s`，
模型又在用它 —— 作者漏掉的一张。做整包时扫描「模型 / 方块状态引用了、
但包里没配 `_n`/`_s`」的贴图，就能自动抓到这种漏网之鱼。

## 5. 盔甲纹饰：只做 `_s`

1140 张纹饰底色，每张配一张 `_s`，**没有 `_n`**。

- 贴图原生 64×32，第一行前 8 个像素是一条 `224, 192, 160, 128, 96, 64, 32, 0` 的灰阶图例（底色里和 `_s` 里都有，看起来是作者工具留下的色阶对照）。
- 真正的纹饰像素：**R = 127**（最光滑）、**G = 0**，B 和 A 随纹饰明暗升高（实测 B 88–144，A 123–174）。
- 空白像素：R = G = B = 0、A = 255。

效果上，纹饰会带一点柔和的自发光/金属感。这套编码和 LabPBR 常见写法（金属用 G = 230–237）不一样，具体给哪个光影用的还没确认，**照抄前先问作者**。

## 7. 连接纹理（CTM）：把接缝抹掉

两组配置：`optifine/ctm/ctm004_05_nolines_dirt.properties` 和 `..._netherrack.properties`。

```properties
matchBlocks=dirt coarse_dirt rooted_dirt
method=overlay
tiles=<skip> <skip> <skip> <skip> <skip> <skip> ctm004_05_dirt_15 <skip> ctm004_05_dirt_15 <skip> ctm004_05_dirt_15 ctm004_05_dirt_15 ctm004_05_dirt_15 ctm004_05_dirt_15 <skip> ctm004_05_dirt_15 <skip>
connectBlocks=minecraft:grass_block:snowy=false minecraft:grass_block:snowy=true podzol mycelium dirt_path
faces=sides
```

- `method=overlay`：把一张"边缘贴图"叠到相邻方块上，抹掉泥土/下界岩和草地、菌丝、灰化土、土径、菌岩之间那条硬边。
- `tiles=` 有 12 个槽位，只有第 6、8、10、11、12、13 槽填了真贴图，其余用 `<skip>` 跳过 → 只在"接边"的情况才画。
- 贴图是 128×128，**只有最上面 16 行（2 个原始像素高）有内容**，其余透明；配套的 `_n` 整张不透明、A 全 255（没有高度）、B 是轻 AO，`_s` 的 G = 0。

这是"让方块之间不出现黑线/硬边"的常用手法，和 PBR 无关，但成品的观感差别很大。

## 8. 随机变体与模型覆盖：破重复感

大面积铺同一种方块时，同一张贴图会连成明显的重复图案。参考包的做法是给重点方块做"随机变体"：

- 9 个方块族各多画 3 张变体：`bedrock`、`bookshelf`、`chiseled_bookshelf_occupied`（5 张）、`deepslate`、`deepslate_top`、`grass_block_top`、`red_sand`、`sand`、`stone`。
- 变体**不是旋转/平移**，是逐像素重新画的（实测和原图平均差 6–26/255），并且每张变体同样配 `_n`/`_s`。
- blockstate 里列出 4 个同权重模型，由游戏随机挑一个：

```json
{ "variants": { "": [
  {"model": "block/stone",              "weight": 1},
  {"model": "block/stone_05_random_02", "weight": 1},
  {"model": "block/stone_05_random_03", "weight": 1},
  {"model": "block/stone_05_random_04", "weight": 1}
]}}
```

- 树叶的 blockstate 另做处理：`waterlogged=false/true` 各列 4 个 `y`（0/90/180/270）同权重随机。

模型覆盖：

- `05_plus_*` 是一套 Blockbench 做的自定义几何，被 `oak_door_bottom_left`、`oak_trapdoor_bottom`、`05_plus_farmland`、玻璃板等模型用 `parent` 引用，给门/活板门/耕地/玻璃板加厚度和边框（对应 102 张 `*_05_plus.png` 贴图，含 `_n`/`_s`）。
- `slime_block`、`spawner` 也换成自定义几何/顶面贴图。
- **只在必要时才覆盖 blockstate**；能用模型 `parent` 解决的（门、活板门）就只覆盖 model，让原版 blockstate 继续指向它。

## 9. 版本适配

- `pack.mcmeta` 里 `supported_formats: [1, 64]`、`min_format: 1`、`max_format: 9999`，让同一个包在 1.12.x–1.21.x 都能加载。
- `lang/zh_cn.json` 覆写了 `pack.incompatible.confirm.*` 文案，直接告诉玩家"忽略不兼容警告、强行加载"。
- 高版本才有的方块（书架 `shelf` 等）用 `05_shelf_*`、`05_plus_*` 模型补上：低版本用不到，高版本正常显示。

---

## 10. 自发光与动画

- 自发光：`_s` 的 A 通道；不发光像素一律 255。
- 动画：底色带 `.png.mcmeta` 时，`_n`/`_s` 通常也各带一份**同样内容**的 `.mcmeta`（实测 31 张底色、31 张 `_s`、23 张 `_n`；少的那几张贴图是火的 `_n` 之类没有的）。
- 不要只给底色写动画：`_n`/`_s` 不跟帧的话，光影下会错位。

## 11. GUI 与字体（和 PBR 无关的"包装"）

- `optifine/color.properties`：改加载界面配色，例如 `screen.loading=7891c2`、`screen.loading.progress=f8ffff`。
- `font/default.json` + `textures/font/pack_05_*.png`：把 `\ue500`–`\ue5ff` 映射成自定义字形，用在 `pack.mcmeta` 描述和 lang 文案里当 Logo/图标。

## 12. 和作者既定规则冲突、**不照搬**的地方

| 参考包做法 | 作者的决定 |
|---|---|
| `_s` G 通道用了 232/235/240/243/245/249 等非规范值 | 按 LabPBR 规范填（铁 230、金 231、铜 234、其他金属 255 等） |
| `_s` R 叠加了 HBAO 压暗 | 不做 |
| 矿石颗粒的 G 用 219 | 第 1 轮训练里明确"用参考包的 219"（这是唯一一条照搬的例外） |
| 纹饰只给 `_s`、B/A 随明暗走 | 待确认，先按本文件的观察记录，不直接照搬 |

## 13. 这套方法能直接用在什么地方

- 给模组做 PBR 时，**不只有方块**：物品、盔甲、实体贴图同样能出 `_n`/`_s`，观感提升明显，而且规则比方块简单（平面高度 + 浮雕）。
- 想让它更像"成品包"，就再加三件事：连接纹理去接缝、重点方块随机变体、`optifine/texture.properties` 声明；前三件都不需要写光影代码。
- 参考包数据来源：`uploads` 里的 `零雾构想 v5003` zip。
